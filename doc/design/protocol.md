# 线协议规范（JT01 / JTPN）

状态: 已采纳（描述当前实现）
日期: 2026-11-23
实现: `core/src/lib.rs`（规范来源）；`dist-web/jt_webd.py` 是第二实现

---

## 0. 总则

- 传输层：**UDP**，规范端口 9000（服务器）。
- 字节序：**小端**。
- 采样格式：**16-bit 有符号整数 PCM**，单声道，规范采样率 48 000 Hz。
- 包类型靠**魔数**区分，两种：`JT01`（音频）、`JTPN`（ping）。
- 解析失败（魔数错 / 长度不符）一律静默丢弃。
- 当前无版本协商、无握手、无鉴权 —— 服务器只认 UDP 源地址作为客户端身份。

## 1. JT01 —— 音频块

```text
偏移   大小   字段            类型   说明
0      4      magic           u8[4]  "JT01" (0x4A 0x54 0x30 0x31)
4      4      client_id       u32    客户端 ID —— 当前恒为 0，未启用（身份 = UDP 源地址）
8      4      seq             u32    块序列号，u32 回绕。发送方每块 +1
12     4      num_samples     u32    本块采样数 n
16     2×n    samples         i16[n] 单声道 PCM，小端
```

**约束**：

- `num_samples` 是 32 位计数，但单包受 UDP MTU 约束 —— 实践中原生端每块 ≤ 4096 采样，网页端恒 480 采样（10 ms）。
- 接收方校验 `包长 == 16 + 2×num_samples`，不等即丢弃（防截断/拼接错位）。
- `seq` 在线上逐块递增，但**当前接收实现不用于重排或丢包检测**（见架构文档 §9）；这是为未来抖动缓冲升级预留的字段。

### 语义（服务器侧）

服务器收到合法 JT01 后：

1. 以**UDP 源地址**为键更新该客户端的 `last_block`；
2. 将其他所有客户端的 `last_block` 混音（饱和求和）成一块；
3. 结果作为一个新的 JT01（`seq = 0`、`client_id = 0`）发回**发送者本人**。

即：每个客户端的下行流速率 = 它自己的上行速率；回包内容是"其他人此刻最新块"的混音。

## 2. JTPN —— ping / RTT 探测

```text
偏移   大小   字段           类型   说明
0      4      magic          u8[4]  "JTPN" (0x4A 0x54 0x50 0x4E)
4      8      timestamp_ms   u64    Unix epoch 毫秒，小端
```

总长固定 **12 字节**。

**语义**：服务器收到 JTPN 后**原样 echo 回发送者**。客户端用 `本地收包时刻 - timestamp_ms` 得 RTT。

注意：`timestamp_ms` 用的是 **wall clock（Unix epoch ms）**而非单调钟。若两端系统时钟有偏差，不影响 RTT 计算（同一台机器发收、时戳原样回来）；但若路径上有设备改写时戳则会失真 —— 当前无此情况。

频率：原生引擎与网页桥均为每 1 s 一次。

## 3. WebSocket 侧协议（网页版，仅浏览器 ↔ jt_webd）

`jt_webd.py` 与浏览器之间的协议与 UDP 线协议**不同层**：

- **二进制帧**（浏览器 → 桥）：裸 PCM，`480 采样 × 2 字节 = 960 字节`/帧。桥负责攒字节、拆帧、套 JT01 头（含自己维护的 seq）。
- **二进制帧**（桥 → 浏览器）：剥头后的裸 PCM payload（长度可变，取决于服务器混音结果）。
- **JSON 文本帧**（双向控制）：

  ```jsonc
  // 浏览器 → 桥
  {"type": "ping", "ts": <client_ms>}          // 桥回 pong 并顺带向服务器发 JTPN

  // 桥 → 浏览器
  {"type": "pong", "ts": <echo>, "server_rtt_ms": <number|null>}
  {"type": "status", "rtt_ms": <number|null>, "tx": <int>, "rx": <int>, "frame_ms": 10}
  ```

- WS 连接参数：`compression=None`，`ping_interval=20`，`max_size=1MB`。

## 4. 未来演进（预留，未实现）

- `client_id`：启用真实客户端 ID，解决 NAT 重绑定导致的"身份漂移"。
- `seq`：客户端抖动缓冲按序号重排 + 丢包掩盖（协议层无需改动）。
- 版本位：`JT01` 末位即 `01`，升级时递增为 `JT02` 并按魔数共存协商。
